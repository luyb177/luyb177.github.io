目标：

掌握Redis中五种核心数据结构的常用命令，使用go-redis库进行操作实践。

NoSQL

Not only SQL （不仅仅是SQL）

泛指非关系型数据库。用于超大规模数据的存储（例如谷歌或Facebook每天为他们的用户收集万亿比特的数据），这些类型的数据存储不需要固定的模式，无需多余操作就可以横向扩展。

NoSQL的特点

  1. 方便扩展（数据之间没有关系，很好扩展）
  2. 大数据量高性能（Redis 可以在一秒内读取11 万次，写入8.1 万次）
  3. 数据类型是多样的（不需要事先设计数据库）

Redis 入门

概述

Redis 是什么

Redis （Remote Dictionary Server）是一个使用ANSI C编写的支持网络、基于内存、分布式、可选持久性的键值对存储数据库。

Redis能干什么

  1. 内存存储、持久化（内存是断电即失，持久化很重要）
  2. 效率高，可以用于高速缓存
  3. 发布订阅系统
  4. 地图信息分析
  5. 计时器、计数器（如实现浏览量）
  6. ……

特性

  1. 多样的数据类型
  2. 持久化
  3. 集群
  4. 事务
  5. ……

Redis是单线程的么？

Redis 单线程指的是「接收客户端请求 -> 解析请求 -> 进行数据读写等操作 -> 发送数据给客户端」这个过程是由一个线程（主线程）来完成的，这也是我们常说 Redis 是单线程的原因。

但是，Redis 程序并不是单线程的，Redis 在启动的时候，是会启动后台线程（BIO）的：

  • Redis 在 2.6 版本，会启动 2 个后台线程，分别处理关闭文件、AOF 刷盘这两个任务；
  • Redis 在 4.0 版本之后，新增了一个新的后台线程，用来异步释放 Redis 内存，也就是 lazyfree 线程。
  • Redis 在 6.0 版本之后，新增了多线程IO

五大数据类型

Redis-Key

这里介绍一些对key的操作

  • KEYS pattern 获取 key
  • EXISTS key [key ...] 判断 key 是否存在
  • MOVE key db 将 {key} 移动到某一个数据库
  • EXPIRE key seconds [NX | XX | GT | LT] 添加过期时间
  • TTL key 查看过期时间
  • TYPE key 查看 value 的类型

String（字符串）

常用命令

  • SET key value [NX | XX] [GET] [EX seconds | PX milliseconds | EXAT unix-time-seconds | PXAT unix-time-milliseconds | KEEPTTL] 设置值
  • GET key 获取值
  • APPEND key value 追加字符串，如果当前key不存在，就相当于set key
  • STRLEN key 获取字符串的长度
  • INCR key 自增 1
  • DECR key 自减 1
  • INCRBY key increment 设置步长，指定增量

有 incrby 自然也有 decrby

  • DECRBY key decrement 设置步长
  • GETRANGE key start end 截取字符串
  • SETRANGE key offset value 替换指定位置开始的字符串

因为 SetEX 和 SetNX 已弃用，都可以被Set所替代

  • SET key value [NX | XX] [GET] [EX seconds | PX milliseconds |

这个命令支持一系列选项，以修改其行为：

  • EX 秒 – 设置指定的过期时间，单位为秒（正整数）。
  • PX 毫秒 – 设置指定的过期时间，单位为毫秒（正整数）。
  • NX – 只有在键不存在时才设置键。
  • XX – 只有在键已存在时才设置键。

一次性批量设置、获取值mset mget msetnx

  • MSET key value [key value ...] 同时设置多个值
  • MGET key [key ...] 同时获取多个值
  • MSETNX key value [key value ...] msetnx 是一个原子性的操作，要么一起成功，要么一起失败
  • GETSET key value 如果存在值，获取原来的值，并设置新的值，即先获取再设置新的，当然这个也已被弃用了，可以在上面set加一个get参数来替换

还有Redis在存储对象相关信息的时候，可以使用String分别存储，也可以json存储，这两种存储方式取决于应用场景，如果只需要用户的某一个特别的信息，使用json存储的话解析需要消耗性能，这个时候分别存储可能更好。

String类似的使用场景：

  • 计数器
  • 统计多单位的数量（uid:12312341:follow value）
  • 对象缓存存储

List（列表）

是基本的数据类型，类似于列表

基于list的特性，我们可以将其当成栈、队列、阻塞队列

  • LPUSH key element [element ...] 将一个值或多个值，插入到列表头部（左）
  • RPUSH key element [element ...] 将一个值或多个值，插入到列表尾部（右）
  • LPOP key [count] 默认情况下，该命令会从列表的开头移除并返回一个元素。当提供了可选的 count 参数时，返回的元素数量将取决于列表的长度，最多为 count 个元素。-
  • RPOP key [count] 默认情况下，该命令会从列表的末尾弹出一个元素。如果提供了可选的 count 参数，回复将包含最多 count 个元素，这取决于列表的长度。
  • LINDEX key index 通过下标获取list的某一个值
  • LRANGE key start stop 返回列表中[start,end]的元素
  • LLEN key 返回列表的长度

Tips

这里可以通过下标获取第一个值，如果第一个值不存在，就阻塞，可以实现生产者和消费者

  • LREM key count element 移除列表中指定个数的value
  • LTRIM key start stop 来截取指定索引处的[start,end]位置的元素
  • rpoplpush 移除列表的最后一个元素，将其移动到指定列表中,

当然，这个也被弃用了，但是也是可以用的

  • LMOVE source destination <LEFT | RIGHT> <LEFT | RIGHT>

这个只需要随意替换相应的参数就可以实现RpopLpush LpopRpush

  • LSET key index element 将列表中指定下标的值替换为另外一个值，即更新操作
  • LINSERT key <BEFORE | AFTER> pivot element将某个具体的value插入到某个元素的前面或者后面，并且在右重复元素的时候，会插入到最新的前面或后面。

小结

  • List 实际上是一个列表，在node 前后都可以插入，在left , right都可以插入值
  • 如果 key不存在，创建新的链表
  • 如果key存在，新增内容
  • 如果移除了所有值，即空链表，也代表不存在
  • 在两边插入或者改动值，效率最高，中间元素，相对来说效率会低一点

Set （集合）

set中的值不能重复

  • SADD key member [member ...] 向集合中添加元素
  • SMEMBERS key 查看指定set的所有值
  • SISMEMBER key member 判断某一个值是不是在set集合中
  • SCARD key 获取set集合中的内容元素个数
  • SREM key member [member ...] 移除set集合中的指定元素
  • SRANDMEMBER key [count] 随机抽选指定数量的元素
  • SPOP key [count] 随机删除指定个数的集合中元素
  • SMOVE source destination member 将一个指定的值，移动到另外一个set集合

数学集合类：

  • 差集 SDIFF key [key ...]
  • 交集 SINTER key [key ...]
  • 并集 SUNION key [key ...]

可以将用户A的所有关注的人放在一个集合，将他的粉丝也放在一个集合，

这样就可以实现共同关注，共同爱好，推荐好友等功能。

Hash（哈希）

Map 集合 ，key-map

  • HSET key field value [field value ...] 设置值
  • HGET key field 获取一个字段值
  • HGETALL key 获取全部的数据
  • HDEL key field [field ...] 删除Hash中指定字段的值
  • HEXISTS key field 判断Hash中指定字段是否存在
  • HKEYS key 只获得所有的key
  • HVALS key 只获得所有的value
  • HINCRBY key field increment 指定增量
  • HSETNX key field value 如果存在则不能设置值

相对应的，hash也是可以存储对象的，和String类型相似

Zset（有序集合）

相对于Set 是有序的，因为其多了一个score

  • ZADD key [NX | XX] [GT | LT] [CH] [INCR] score member [score member...] 添加值
    • GT仅当新分数大于当前分数时，才更新现有元素。此标志不会阻止添加新元素。
    • LT仅在新评分小于当前评分时更新已存在的元素。此标志不会阻止添加新元素。
  • ZRANGE key start stop [BYSCORE | BYLEX] [REV] [LIMIT offset count] [WITHSCORES] 排序
    • 携带参数rev可以从大到小排
    • 携带参数withscores 可以输出分数
  • ZREM key member [member ...] 删除指定元素
  • ZCARD key 统计 zset 中元素数量
  • ZCOUNT key min max 获取指定分数区间元素的数量

其中zrange

元素的默认顺序是从最低分到最高分。具有相同分数的元素按字典顺序排序。

可选的 REV 参数可以反转顺序，使得元素按最高分到最低分排序，且分数相同的情况按逆字典顺序排序。

剩下的一些api，之后在需要的时候就可以自己查阅官方文档

Zset 应用场景

  • 对消息进行加权，普通消息 1 ，重要消息 2，带权重进行处理
  • 排行榜应用的实现

剩下的数据类型，还有

  • 位图 Bitmaps: 基于字符串类型，可以对每个位进行操作。
  • 超日志 HyperLogLogs: 用于基数统计，可以估算集合中的唯一元素数量。
  • 地理空间 Geospatial: 用于存储地理位置信息——可以应用于“附近好友”等功能
  • 发布/订阅 Pub/Sub: 一种通信模式，允许客户端订阅消息通道，并接收发布到该通道的消息
  • 流 Streams: 用于消息队列和日志存储，支持消息的持久化和时间排序。

这些数据类型各有自己的功能，可以在需要的时侯查看官网。

核心差异点

  1. Context 上下文

go-redis的所有操作都需要传入context.Context,用于超时控制和取消操作

  1. 返回值处理

Redis命令行直接返回结果，而go-redis返回结果+错误

实际应用场景

  1. 缓存应用

其他的应用场景有

  • 消息队列

  • 合理设计key
  • 选择合适的数据结构：根据业务需求选择String、Hash、List、Set、Zset
